# Adoption Strategy

The protocol is designed for bottom-up network effects.

## The unit is an agent
Make it easy for one agent to emit a Trigger record without replacing an existing stack.

### Stage 1
One person wraps one agent: propose → authorize → execute → audit.

### Stage 2
A team shares the same records.

### Stage 3
Different implementations exchange the same authorization and audit format.

### Stage 4
Downstream systems can require a valid Trigger receipt before accepting consequential side effects.

## Why this can compound

Each decision can add evidence, outcomes, reusable policy, authority context, and precedent. The shared object becomes a decision network.

## Adoption principles

Zero vendor lock-in. Language-neutral schemas. Copy/paste examples. Conformance tests. Small core. Adapters instead of proprietary integrations. Useful with one user. Useful without an LLM.

Do not sell governance. Make decision boundaries useful.
